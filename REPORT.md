# Architecture

The implementation is a single Node.js process with a local HTTP banking sandbox, a Playwright browser adapter, a discovery provider and a deterministic executor. The sandbox is a server-rendered, table-based multi-page application without test IDs or a task API. Search → record detail → savings review is deliberately read-only. This lets the project exercise navigation, parameterization, extraction, exceptional states and guardrails without real financial records.

The model receives a redacted accessibility snapshot and the completed action history. It selects one structured action at a time; the executor validates policy and performs the browser action. The finish decision is only advisory: the adapter must verify a real review heading and typed outputs before the capability is saved. A genuine discovery used five Responses API calls. No replay path calls the model. The successful action list is separated from reasoning, response metadata and observations. A deterministic compiler attaches the domain contract and extraction selectors; the model does not invent an unrestricted capability schema.

The sandbox, policy and contract are intentionally specific to one vendor workflow. This makes the security boundary reviewable, at the cost of general discovery across arbitrary workflows. The discovery provider is a plain fetch call with a schema-constrained response, 45-second request timeout, no automatic retry and `store:false`. Failure cannot silently turn into scripted “discovery.” The same workflow succeeds offline using the saved artifact.

# Artifact schema

The JSON artifact separates `schemaVersion` (serialization compatibility), `vendor` (application compatibility), `revision` (capability release), typed `inputs`, typed `outputs`, `steps` and `checkpoint`. Member input is a five-digit string, marked sensitive. Fill steps carry an input reference, never the concrete member value. Output fields carry accessible label targets and numeric/string types; output extraction uses this contract. Steps have action plus exact label/role/name locators. The readable targeting note explains the unique-match requirement.

The runtime validator accepts only schema v1, Harbor v1, the known capability and the supported action/parameter set. Inputs reject extra keys and malformed references. This is an intentionally closed contract rather than a universal workflow language. Schema versioning, vendor binding and parameter references are important; adding arbitrary script execution or embedding browser handles would make artifacts unsafe and non-portable. Production should additionally sign immutable revisions and require approval before unattended invocation. Here local artifact review is the approval boundary.

# Determinism & error handling

Replay follows the ordered artifact without model decisions. Labels, buttons and links are matched by exact accessible name, and every target must resolve uniquely. Navigation waits for DOM content; Playwright waits for control actionability, with a bounded 2.5-second timeout. There is no index, guessed selector or coordinate fallback. Output extraction verifies the checkpoint, one match per field, a decimal number and USD. A capability cannot report success merely because its last click returned.

Before each action and before extraction, state detection distinguishes `business_outcome` (`NOT_FOUND`, invalid reference), a known recoverable maintenance interstitial, session expiry requiring intervention, and hard permission failure. Interstitial recovery is bounded to three state checks. Slow loading is handled by browser waits; beyond the bound it fails, rather than retrying potentially mutating clicks. Unexpected JavaScript dialogs are dismissed and become an explicit hard failure. Missing/ambiguous targets and policy blocks stop with step, expected target and redacted observed state. A richer redacted accessibility snapshot is saved on failure. Result status can also be `intervention` when no operator path was requested. Invalid input is rejected before execution; application validation is a business outcome.

Tests exercise success with a second input, not-found, validation, permission, interstitial, slow load, session expiry, missing target, and handoff. They use a fixture flow; separately, the demo replays the actual discovered artifact. No claim is made that screenshot-based replay is robust or that a completely inaccessible canvas can be automated with this adapter.

# Heterogeneity & multi-tenant

The seam is the surface adapter's observe, action, state, outputs and evidence methods. The engine and ownership model do not need browser element handles. A legacy web adapter could add frame paths and scoped accessible targets; a desktop adapter could implement window/UIA control selectors and OS actionability waits. The artifact would introduce a tagged locator union under a new schema version. Coordinates should be bounded anchors with a visual checkpoint, not an unqualified fallback when semantic identity fails.

For multiple institutions, identify a base capability by vendor/product/version and immutable revision. Tenant profiles bind entry origin, approved routing, accessible-name overrides and policy, without widening the base permissions. Validate both before execution. A version or fingerprint mismatch stops and requests review; smoke replay on synthetic data can certify profiles. A tenant override must remain explicit, reviewable and narrower than the base action semantics. This project implements one vendor and one sandbox, not tenant management or desktop automation. Branded text is not used as control identity.

# Escalation & handoff

The live surface owns the control state. On expiry or a stuck discovery, automation pauses, marks owner human, emits intervention context, and opens a loopback console. The operator repairs the **same browser Page/context**, then posts resume using an unguessable in-memory token. Browser actions through the automation adapter reject while human-owned. Page listeners audit clicked/changed control names without capturing typed values. On return, the origin/route policy is checked, ownership returns to automation, and the executor checks state before continuing. A hard replay failure can hand off for manual completion, but it must still satisfy the final output checkpoint.

The console is intentionally minimal and the browser window provides manual control. Timeout releases the local console and reports failure; it does not guess that the operator consented. The integration test simulates an operator clicking session restore and posting resume; it proves control transfer and browser identity, but is not human evidence. A real user can perform the exact headed command in README. Production would need authenticated operator routing, durable leases, event acknowledgements, replay cursor checkpoints, access controls and audit storage. This implementation assumes one operator and one process; it does not enforce physical browser exclusivity.

# Safety

The permission boundary independently checks action type/control name and exact origin/route before and after actions. Context-level request interception prevents navigation or subrequests to unapproved origins/routes, including the irreversible commit route. Risky controls are blocked, not delegated to the model's judgment. Human control is explicit; manual behavior is audited, and network allowlisting remains active.

No real credentials or PII enter the demo. Inputs are resolved in memory at execution. Artifact steps contain references, observations mask member references and decimal amounts, and persisted output fields are scrubbed by key so integer balances are also removed. Secrets and emails have additional string masking. API response text is parsed, only sanitized decision fields and response IDs/usage are logged, and raw API failures are not printed. Raw screenshots and browser traces are deliberately omitted; the redacted accessibility snapshot provides richer failure evidence. This is not a general-purpose PII detector: arbitrary names, unknown formats and free-text UI data need a vendor-specific field policy and production redaction tests before any real financial deployment. Model inputs are already masked. A local provider API still receives goal and control structure; `store:false` alone is not a compliance guarantee.

# Cuts

I kept a real end-to-end browser slice, contract, errors, policy, evidence and same-session handoff. I omitted queues, distributed locks, real bank access, desktop code, an authenticated operator dashboard, a capability catalog and cross-tenant runtime support. The target uses semantically named controls in legacy-style markup; it does not pretend to demonstrate pixel-only or frameset control. Workflow and output contract compilation are domain-specific. Existing artifacts are locally editable and unsigned. There is no automatic re-recording, blanket retry or LLM fallback during replay.

Next I would harden privacy with explicit field-level observation projection; package a formal schema and signed approval states; add frame/UIA locator adapters; and build authenticated operator leases with step checkpoint persistence. Those extensions should preserve the key invariant: a model discovers a constrained capability, deterministic replay executes it, and uncertainty stops for deliberate intervention.
